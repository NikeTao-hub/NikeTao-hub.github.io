# 在 VS Code 中写博客

本机使用 Hugo Extended 0.165.0、Node.js 22 或更新版本。Front Matter 扩展已配置；如果扩展未出现，请重新加载 VS Code 窗口。

1. 在 VS Code 打开整个 `niketao-blog` 文件夹，先通过源代码管理拉取最新内容；有未提交修改时先处理自己的修改。
2. 命令面板（macOS：Cmd+Shift+P）选择“任务: 运行任务”→“博客：新建文章”。输入标题并选择分类。终端会给出新文件路径，Cmd+单击打开。
3. 编辑正文；Front Matter 面板可调整标题、日期、简介、分类、标签、封面 URL、目录和草稿开关。日期命名的新建任务与现有文章命名一致。
4. 运行“博客：本地预览（含草稿）”，打开 http://localhost:1313/blog/。保存后自动更新。停止时使用“任务: 终止任务”。也可用 Front Matter 的启动服务按钮，两种方式只选一种，避免端口冲突。
5. 图片：运行“博客：上传图片到 Cloudinary”，输入图片完整路径。复制输出的 Markdown 到正文，或复制 URL 到封面字段。支持 JPG、PNG、WebP、GIF、AVIF，最大 20 MB；保留原图，不自动压缩。上传只在你执行该任务时发生。
6. 发布前把 `draft` 改为 `false`，日期不能晚于发布时间；运行“博客：发布前构建检查”。
7. 在 VS Code 源代码管理中检查差异、暂存、提交并推送。推送 main 会触发现有 GitHub Pages 部署，保存文件本身不会发布。

网页后台仍可使用：网页编辑之后，本地再次编辑前先拉取。同一篇文章不要同时在两处修改。不要重命名已经发布的文章文件，以免改变链接。

新文章默认是草稿。网页端保存成功不代表博客已公开：关闭草稿开关、保存并等待部署后才公开。旧文章没有 `draft` 字段时仍正常发布。Git 仓库中的草稿不等于保密文档；若仓库公开，源文件仍公开。

## 私有访问统计

接入方式为 Umami：博客页面仅发送访问事件，统计结果仅在需要登录的 Umami 管理端查看。博客首页和文章不显示访问量、访客列表或统计入口。博客 `/blog/admin/` 中提供管理入口，点击后需要 Umami 自己的登录；Decap 登录和 Umami 登录相互独立。

GitHub Pages 的静态 `/admin/` 地址本身不是权限边界。这里不保存统计结果、管理密码、API token，也不使用公开分享链接或 iframe。即使他人知道统计服务地址，也必须通过统计服务的服务端权限检查才能读取数据。关闭 Umami 的公共分享，不创建公开统计链接。

当前已配置 Umami Cloud 的脚本和网站 ID，`hugo.toml` 中 `params.analytics.enabled = true`；部署到线上后开始采集。后台入口指向 Umami Cloud 的美国区域网站列表。需要暂停采集时将 `enabled` 改为 `false` 并重新部署。以后更换统计网站时需要更新：

1. Umami 网站设置中的脚本 HTTPS 地址 `scriptURL`；
2. 对应的网站 UUID `websiteID`；
3. 需要登录的管理面板 HTTPS 地址 `dashboardURL`，不能是 `/share/` 链接；
4. 填完后将 `enabled` 设为 `true`，构建并部署。

网站 UUID 是用于写入事件的公开标识，不是读取统计的凭据。采集仅用于生产构建及正式域名，本地 Hugo server 不加载统计脚本；管理页不加载采集脚本。尊重浏览器 Do Not Track，并排除 URL 查询参数和 hash。

上线后需验证：普通博客无统计界面；无痕窗口打开统计管理地址必须登录；本人登录后访问博客，确认产生访问事件并将面板时区设为 Asia/Shanghai（若服务支持）。不要用已有登录态来验证访问控制。拦截器和 Do Not Track 可能造成漏计；只能从启用时开始收集，不会补齐历史访问。

资料：[Front Matter](https://frontmatter.codes/docs/content-creation/)、[Umami 脚本配置](https://docs.umami.is/docs/tracker-configuration)。
