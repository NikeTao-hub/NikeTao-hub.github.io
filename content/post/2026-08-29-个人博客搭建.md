## 1. 为什么自己搭建博客

一开始只是想拥有一个属于自己的个人博客。

相比直接使用现成的博客平台，我更希望：

* 网站完全属于自己
* 可以使用自己的域名
* 支持 Markdown
* 支持 LaTeX 数学公式
* 可以方便地插入图片
* 可以记录科研、技术和生活
* 最好能够直接在网页后台写文章
* 不希望维护复杂的服务器

因此最终选择了：

**Hugo + GitHub Pages + Decap CMS**
其中：

* Hugo：负责生成静态网站
* GitHub：保存博客源代码和文章
* GitHub Pages：负责网站托管
* Decap CMS：提供网页后台
* Vditor：作为文章编辑器
  最终的架构大致如下：

```
                    ┌──────────────┐
                    │   浏览器访问   │
                    │  niketao.com │
                    └───────┬──────┘
                            │
                            ▼

                    └───────┬──────┘
                            │
                            ▼

                            ▼
                    静态 HTML / CSS
                            │
                            │
```

# 3. 使用 Stack 主题

博客使用的是 Hugo 的 Stack 主题。

Stack 的整体风格比较适合技术博客，同时支持文章归档、标签、目录等功能。

网站基本配置放在：

```
hugo.toml
```

例如：

```
baseURL = "https://niketao.com/"
languageCode = "zh-cn"
title = "Nike Tao"

theme = "hugo-theme-stack"

[params]
    mainSections = ["post"]

[params.sidebar]
    emoji = "🌌"
    subtitle = "Research · Technology · Life"
```

配置首页、文章和关于页面。

# 4. GitHub Pages 自动部署

博客最终部署在 GitHub Pages。

每次向：

```
main
```

分支 push 代码以后，GitHub Actions 自动执行 Hugo 构建。

核心流程是：

```
git push
    ↓
GitHub Actions
    ↓
Checkout
    ↓
安装 Hugo
    ↓
hugo --gc --minify
    ↓
生成 public/
    ↓
上传 Pages artifact
    ↓
Deploy to GitHub Pages
```

# 6. 为什么还需要 Decap CMS

由于Hugo 本身是静态网站生成器。这意味着默认情况下写文章需要本地编辑 Markdown，再用git push到Github项目中去。对于非专业人士，自然是希望越简单越好，于是产生了在博客后台

```https://niketao.com/admin/

```

写完直接发布，Decap CMP恰好满足了我的这个需求。

# 7. GitHub OAuth 登录

然而在Decap CMS 使用 GitHub backend 时，需要解决 GitHub OAuth 认证登录的问题

我使用 Cloudflare Workers 搭建了一个简单的 OAuth 服务。
由OAuth Worker 提供：

```
/auth
/callback
```

两个主要接口。

登录时访问：

```
/auth?provider=github
```

然后跳转到 GitHub 授权。

授权完成以后 GitHub 回调：

```
/callback?provider=github
```

最终把 GitHub access token 传回 Decap CMS。
